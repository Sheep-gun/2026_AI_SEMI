# P8-DG-SCR AER 컨트롤러 최종 검증 결과

## 먼저 읽을 핵심

P8-DG-SCR은 P7-GE의 외부 기능과 이벤트 처리 순서를 바꾸지 않고, 같은 기능을
더 작은 표준셀과 더 적은 전력으로 구현하기 위해 내부 표현을 다시 정리한 설계다.
16개 source의 비동기 요청을 각각 2단 플립플롭으로 동기화하고, source마다 한
칸씩 총 16개의 대기칸과 한 칸의 출력 register를 유지한다. 수신기가 계속 준비된
경우의 최대 처리율도 P7-GE와 같은 clock당 1 event다.

P8-DG-SCR에서 새로 결합한 기법은 다음 네 가지다.

1. 다음 우선순위를 Gray code 자체로 저장하는 **direct Gray state**
2. 후보 존재 여부를 한 번만 계산해 여러 선택 단계가 함께 쓰는 **shared OR tree**
3. 16개 source의 신규 요청 접수를 하나의 bit-vector 식으로 계산하는
   **vector request acceptance**
4. 상태의 역할에 따라 비동기 reset, 동기 clear, resetless를 나누는
   **reset partition**

같은 조건의 P7-GE와 비교하면, Genus 합성 cell area는 11.93%, 동일 traffic을
반영한 VCD 전력 보조 관찰값은 9.525% 감소했다. Innovus 배치·배선 후에는 cell area가
5.03%, vectorless power 추정치가 4.58% 감소했다. 대신 post-route core setup
slack은 +4.350 ns에서 +3.235 ns로 줄었다. 즉, P8-DG-SCR은 timing 여유 일부를
사용해 면적과 전력을 줄인 설계이며, 모든 지표가 동시에 좋아졌다고 주장하지
않는다. Core setup +3.235 ns, CDC max-delay +0.201 ns와 hold +0.028 ns로 현재
10 ns 및 synchronizer 물리 제약을 통과했다.

> **공정 범위 주의:** 아래 PPA 수치는 **서버 제공 FPR 180 nm reference
> kit에서의 잠정 비교**다. 이 kit가 대회 주최측의 공식 제출 공정이라고 확인된
> 것은 아니며, 특정 foundry의 공식 sign-off 결과로 해석해서는 안 된다. P7-GE와
> P8-DG-SCR을 같은 library와 같은 제약으로 비교해 구조의 상대 효과를 확인한
> 결과다.

## 1. P8-DG-SCR이 전달하는 것

AER(Address Event Representation)는 여러 event source 가운데 **어느 source가
발화했는지 주소로 표현해 전달하는 방식**이다. 이 설계에는 16개의 source가 있고,
출력에는 선택된 source 번호를 나타내는 4-bit 주소 버스 하나만 있다. Timestamp,
뉴런의 membrane 값이나 별도의 payload를 이 버스에 싣지는 않는다.

Source 쪽은 active-high 4-phase REQ/ACK 규약을 사용한다. 한 source의 동작은
`REQ 상승 → ACK 상승 → REQ 하강 → ACK 하강` 순서다. Source는 ACK를 볼 때까지
REQ를 유지해야 한다. P8-DG-SCR의 ACK는 최종 수신기까지 전달이 끝났다는 뜻이
아니라, 해당 event가 controller의 pending 칸 또는 출력 register에 **안전하게
접수되었다는 조기 응답(early ACK)** 이다.

수신기 쪽은 등록된 `out_valid/out_ready` 규약을 사용한다. `out_valid=1`이면
`out_addr`에 유효한 source ID가 있고, 같은 clock에서 `out_ready=1`이면 수신기가
그 event를 가져간다. 수신기가 `out_ready=0`으로 멈춘 동안에는 controller가
`out_valid`와 `out_addr`를 그대로 유지한다.

## 2. P7-GE에서 그대로 유지한 기능 계약

P8의 면적 감소가 저장 기능이나 출력선을 외부로 떠넘긴 결과가 되지 않도록,
P7-GE의 기능 계약을 그대로 고정했다.

| 계약 항목 | P7-GE와 P8-DG-SCR의 공통 조건 |
|---|---|
| 비동기 입력 보호 | 16개 source 각각에 2FF CDC, 총 32 FF |
| 내부 대기 저장 | source별 pending 1 bit, 총 16 events |
| 출력 저장 | 등록된 output 1 event |
| 최대 내부 보유량 | 접수됐지만 아직 전달되지 않은 event 최대 17개 |
| source 응답 | 내부 접수 시 early ACK |
| 출력 bus | 4-bit source-ID bus 1개 |
| 최대 처리율 | `out_ready=1`일 때 clock당 최대 1 event |
| 공정성 | 계속 기다리는 source는 최대 16번의 service decision 안에 선택 |
| stall 해석 | receiver stall 동안은 service decision이 없으므로 공정성 횟수에서 제외 |

여기서 CDC(Clock Domain Crossing)는 controller clock과 무관한 순간에 바뀌는
REQ를 clock 기반 내부 회로로 넘기는 경계다. 첫 번째 플립플롭이 비동기 변화를
받고, 두 번째 플립플롭이 한 clock 뒤의 값을 다시 받는 2FF synchronizer를
source마다 둔다. 이는 metastability가 다음 논리로 퍼질 확률을 낮추는 표준적인
디지털 구조지만, 실제 silicon의 MTBF를 측정한 것은 아니다.

Pending은 controller가 ACK로 접수했지만 아직 출력하지 못한 event를 기억하는
source별 1-bit 대기칸이다. 한 source가 pending인 동안에는 같은 source의 두 번째
event를 새로 저장할 공간이 없으므로, source는 ACK가 내려간 뒤 다음 4-phase
transaction을 시작해야 한다.

공통 101-event fixed-demand workload에서도 두 설계는 같은 경계 동작을 보였다.
입력 event와 도착 시각을 고정했을 때 P7-GE와 P8-DG-SCR의 출력 주소 순서가
같았고, 주소 bit 전환 횟수도 모두 106회였다. 두 설계 모두 101개를 오류 없이
처리했으며, saturation 출력 구간은 630 ns, stall 해제 전에 보낸 early ACK는
5개로 같았다. 따라서 아래 PPA 차이는 workload나 출력 순서를 바꿔 얻은 결과가
아니다.

## 3. 내부 구조와 네 가지 개선 기법

![P8-DG-SCR 구조](../docs/architecture/aer_p8_dgscr_structure.svg)

### 3.1 Direct Gray state: 변환하지 않고 Gray 순번을 직접 저장

P7-GE는 4-bit binary epoch을 저장하고 매 service decision마다 1을 더한 뒤,
`binary XOR (binary >> 1)` 연산으로 Gray 우선순위를 만들었다. 여기서 epoch은
event 발생 시각이 아니라, **중재기가 다음에 어느 주소를 먼저 찾아볼지 나타내는
내부 순번 상태**다.

P8-DG-SCR은 binary epoch을 두지 않고 다음 Gray 값을 상태에 직접 저장한다.
한 번의 실제 처리 결정마다 Gray 상태 bit 하나만 바뀌며 다음 순서를 순환한다.

```text
0, 1, 3, 2, 6, 7, 5, 4, 12, 13, 15, 14, 10, 11, 9, 8
```

모든 source가 계속 pending인 경우 실제 출력 주소도 위 순서와 정확히 일치한다.
Sparse traffic에서는 현재 우선 주소가 비어 있을 수 있으므로 대기 중인 다른
주소를 선택하지만, 우선순위 상태 자체는 매 service decision마다 다음 Gray
상태로 진행한다.

공정성의 근거는 16개의 우선 주소를 빠짐없이 순환한다는 점이다. 어떤 source가
계속 pending이면 늦어도 우선순위가 자신의 주소와 같아지는 결정에서 최우선으로
선택된다. 따라서 bound는 최대 16 **clock**이 아니라 최대 16 **service
decisions**다. 수신기가 멈춰 실제 선택이 진행되지 않는 시간은 여기에 포함하지
않는다.

### 3.2 Shared OR tree: 후보 존재 계산을 한 번 만들어 함께 사용

OR tree는 16개 pending 후보 가운데 어느 구역에 최소 한 개의 event가 있는지
알아내는 계층형 조합 회로다. P8-DG-SCR은 16개 후보를 8개 pair, 4개 quarter,
2개 half, 전체 valid 순서로 묶는다. 중재기는 선호하는 half에 event가 있으면
그쪽으로 내려가고, 비어 있으면 반대쪽으로 간다. 이 판단을 네 주소 bit에 대해
반복하면 실제 pending source 하나가 선택된다.

P8에서는 이 균형 OR tree 하나를 최종 `grant_valid` 판단과 네 단계의 주소 선택이
공유한다. 같은 후보 존재 조건을 서로 다른 식에서 다시 reduction하지 않도록 RTL을
구조화했다. 기능적으로는 pending 주소 `i` 가운데
`unsigned(i XOR epoch_gray)`가 가장 작은 주소를 고르는 P7의 선택 규칙과 같다.

### 3.3 Vector request acceptance: 16개 접수 조건을 한 식으로 묶기

P8은 다음 bit-vector 연산으로 새 요청을 접수한다.

```text
accept_mask      = synchronized_REQ & ~ACK & ~pending
accepted_pending = pending | accept_mask
```

`accept_mask`의 각 bit는 해당 source의 동기화된 요청이 올라와 있고, 아직 ACK하지
않았으며, 그 source의 pending 칸이 비어 있을 때만 1이 된다. 따라서 여러 source가
같은 clock에 요청해도 각 source의 빈 칸에 동시에 접수할 수 있다. 출력 bus는
하나이므로 한 clock에 내보내는 event는 최대 하나지만, 16개 pending이 burst를
먼저 흡수한다.

이 동작은 P7의 source별 반복문과 논리적으로 같지만, synthesis가 공통 bitwise
조건을 인식하고 공유하기 쉬운 형태로 표현했다. 새로운 기능을 추가한 것이 아니라
같은 접수 규칙을 더 직접적인 데이터 경로로 만든 것이다.

### 3.4 Reset partition: 모든 플립플롭에 같은 reset cell을 쓰지 않기

Reset pin이 있는 플립플롭은 일반 플립플롭보다 셀 면적이 크거나 reset 배선의
부하를 추가할 수 있다. P8-DG-SCR은 총 75개 상태 FF를 없애지 않고, 각 상태가
실제로 어떤 초기 조건을 필요로 하는지에 따라 세 종류로 나눴다.

| reset 분류 | 상태 | 수량 | 역할 |
|---|---|---:|---|
| 비동기 reset | `reset_release_q[1:0]` | 2 | 외부 reset을 clock 없이 즉시 받고, 해제는 두 clock에 걸쳐 진행 |
| resetless | request synchronizer 32개 + `out_addr` 4개 | 36 | 입력을 두 번 sampling하며, 주소는 valid가 0일 때 사용하지 않음 |
| 동기 clear | ACK 16개 + pending 16개 + Gray epoch 4개 + `out_valid` 1개 | 37 | 두 release clock 동안 0으로 clear되는 실제 protocol/core 상태 |
| **합계** |  | **75** | P7과 동일한 상태 수 |

Resetless는 “아무 값이어도 동작 중 그대로 사용한다”는 뜻이 아니다. 두 request
synchronizer stage는 clock을 받으면서 실제 입력값으로 채워지고, core는 두 번의
release edge 동안 계속 clear되어 그 값이 안정될 시간을 확보한다. `out_addr`는
초기값을 강제하지 않지만 `out_valid=0`일 때는 인터페이스상 don't-care이므로
수신기가 읽어서는 안 된다.

외부에서 직접 보이는 `src_ack`와 `out_valid`는 `core_rst_n`과 AND하여 격리한다.
따라서 동작 중 reset이 assertion되면 clock이 멈춰 있어도 ACK와 valid가 즉시
0으로 내려간다. 내부의 37개 core FF는 clock edge에서 동기적으로 clear된다.
Reset 해제 뒤 정상 동작을 시작하려면 **두 번의 상승 clock edge가 공급되어야
한다**. 두 번째 edge까지 core를 clear한 다음에만 ACK와 valid 격리가 풀린다.

## 4. 기능, 공정성, CDC와 reset 검증

RTL simulation은 작성한 SystemVerilog의 동작을 확인하고, gate simulation은
synthesis가 만든 표준 논리 gate netlist에서도 같은 기능이 유지되는지 확인한다.
Vivado 기반 RTL 및 post-synthesis gate 시험 결과는 다음과 같다.

| 시험 | RTL | Gate | 확인한 내용 |
|---|---:|---:|---|
| Broad regression | 139/139, 오류 0 | 139/139, 오류 0 | 단일·동시·burst·stall·saturation·hotspot·reset-held 요청 |
| Full-backlog 순서 | 정확한 Gray 순서 | 정확한 Gray 순서 | 16개 source 동시 대기 시 순서 일치 |
| Frozen random masks | 64/64, 오류 0 | 64/64, 오류 0 | 서로 다른 pending 조합의 선택 결과 |
| 최악 공정성 위치 | 16 decisions | 16 decisions | starvation bound 충족 |
| CDC phase sweep | 192/192, 오류 0 | 192/192, 오류 0 | clock의 여러 위상에 들어오는 비동기 요청 |
| Clockless/mid-phase reset | PASS | PASS | clock 없는 assertion과 transaction 중 reset |

Cadence Xcelium에서도 별도로 RTL 시험을 다시 실행했다. Broad 139/139,
full-Gray·64 random-mask·worst-16 공정성, CDC 192/192, clockless/mid-phase reset이
모두 오류 0으로 통과했다. 이는 한 simulator에서만 우연히 통과한 결과가 아님을
확인하기 위한 교차 검사다.

Reset 전용 시험은 다음 경계를 직접 확인했다.

- clock이 없는 동안 reset을 assertion해도 ACK와 valid가 즉시 0이 되는가
- reset 해제의 첫 번째와 두 번째 clock에서 core state가 clear되는가
- reset 동안 계속 high였던 REQ가 해제 후 정확히 한 번 접수되는가
- transaction 도중 reset에서 phantom ACK, pending 또는 valid가 생기지 않는가
- receiver stall 중 `out_valid`와 `out_addr`가 안정적으로 유지되는가

Conformal LEC(Logic Equivalence Checking)는 RTL과 Genus netlist가 같은 상태
전이와 출력을 만드는지 수학적으로 비교하는 단계다. State point 75개가 75/75
모두 equivalent였고, primary output 21개도 모두 equivalent였다.
Nonequivalent, abort, unknown 비교점은 각각 0이었다.

## 5. 서버 제공 FPR 180 nm reference kit에서의 잠정 PPA 비교

PPA는 Power, Performance, Area의 약자다. 여기서 Genus는 RTL을 표준셀
netlist로 합성하고, Innovus는 그 셀을 실제 core 영역에 배치한 뒤 금속선으로
연결한다. Genus 비교는 10 ns clock과 1 ns I/O delay를 사용했으며 명시적인
clock uncertainty는 적용하지 않았다. Innovus 비교에는 10 ns clock, 0.2 ns
clock uncertainty와 Metal1~Metal6를 동일하게 적용했다.

### 5.1 Genus 합성

| 항목 | P7-GE | P8-DG-SCR | 변화 |
|---|---:|---:|---:|
| Mapped cells | 236 | **232** | -1.69% |
| Cell area | 7,248.226 µm² | **6,383.362 µm²** | **-11.93%** |
| Worst data path | **2.508 ns** | 3.130 ns | +0.622 ns, 느려짐 |
| Setup slack | **+7.268 ns** | +6.657 ns | -0.611 ns, 통과 |
| Vectorless power | 0.887720 mW | **0.848839 mW** | **-4.38%** |

Cell 수는 4개만 줄었지만 면적은 11.93% 감소했다. 두 설계 모두 상태 FF는
75개지만 sequential cell area가 5,255.712에서 4,144.694 µm²로 1,111.018 µm²
줄었다. 반대로 조합·inverter·buffer 면적은 1,992.514에서 2,238.667 µm²로
246.153 µm² 증가했다. 따라서 이번 mapping의 순면적 이득은 reset partition에
따른 sequential cell 감소가 지배한다. Shared tree와 vector 접수식은 RTL의 중복
표현을 정리했지만 mapped 조합 면적을 P7보다 줄였다고 독립적으로 주장하지 않는다.
Worst data path도 0.622 ns 길어졌다.
현재 명시적 uncertainty가 없는 10 ns Genus 제약에는 +6.657 ns의 여유가 있지만, P8의 선택 논리가 P7보다
빠르다고 해석하면 안 된다.

### 5.2 동일 101-event VCD 전력

VCD(Value Change Dump)는 simulation 동안 각 신호가 언제 0과 1 사이에서
바뀌었는지 기록한 파일이다. Genus에 이 활동 정보를 넣으면 모든 신호에 임의의
기본 전환율을 주는 vectorless 방식보다 workload에 가까운 전력 추정이 가능하다.
Annotation coverage는 합성된 sequential signal 가운데 VCD 활동이 연결된 비율이다.

| 항목 | P7-GE | P8-DG-SCR | 변화 |
|---|---:|---:|---:|
| Contract VCD power | 0.686263 mW | **0.620896 mW** | **-9.525%** |
| Sequential annotation | 100.00% | 100.00% | 동일 |

두 run 모두 RTLStim2Gate mapping을 켜 STIM-0551 경고를 제거했고 sequential
output과 RTL driver-net 주석률은 100%였다. 그러나 전체 gate driver-net의 Asserted
비율은 P7 37.10%, P8 51.21%로 달랐다. 두 DUT가 같은 101-event workload, 출력
순서와 주소 전환 106회를 사용해도 gate-level coverage는 완전히 같지 않다. 따라서
0.686263/0.620896 mW와 -9.525%는 방향성 보조 관찰이며 clean matched-coverage
전력 근거로 사용하지 않는다.

### 5.3 Innovus post-route

| 항목 | P7-GE | P8-DG-SCR | 변화 |
|---|---:|---:|---:|
| Placed cells | **292** | 313 | +7.19% |
| Cell area | 8,063.194 µm² | **7,657.373 µm²** | **-5.03%** |
| Core setup slack | **+4.350 ns** | +3.235 ns | -1.115 ns, 통과 |
| CDC max-delay slack | 별도 제약 없음 | **+0.201 ns** | 0.9 ns 제약 통과 |
| Hold slack | +0.006 ns | **+0.028 ns** | +0.022 ns, 통과 |
| Reset recovery slack | +8.366 ns | **+9.104 ns** | +0.738 ns |
| Reset removal slack | **+0.340 ns** | +0.043 ns | -0.297 ns, 통과 |
| Vectorless power | 0.85619239 mW | **0.81695915 mW** | **-4.58%** |
| DRC violations | 0 | **0** | PASS |
| Connectivity problems | 0 | **0** | PASS |

P8의 instance 수는 CDC pair max-delay와 hold를 동시에 닫기 위한 buffer 때문에
292에서 313으로 늘었다. 그러나 resetless/synchronous-clear FF가 더 작은 셀로
mapping돼 총 cell area는 5.03% 감소했다. 따라서 이 결과를 “셀 개수를 줄인 설계”로
설명하지 않고, 더 많은 작은 buffer를 포함해도 전체 면적과 전력이 감소한
physical tradeoff로 해석한다.

첫 P8 Innovus run은 전용 clock buffer가 없어 0.314 pF root load가 0.312 pF
library limit를 넘었으므로 최종 결과에서 제외했다. 최종 run은 P7과 같은
`CLKBUFX20` driver를 사용하고 clock-tree max-capacitance, resistance, length,
fanout와 slew violation이 모두 0이다. Cadence가 RTL `ASYNC_REG`를 무시하므로
Genus mapped-cell preserve, Innovus dont-touch/soft-guide와 request pair 0.9 ns
max-delay도 명시했다. 이 안전 제약과 hold buffer 비용을 포함한 최종 면적·전력이
5.03%, 4.58% 감소했다. 동일-workload Genus VCD의 9.525% 감소는 driver-net
coverage 차이가 남은 방향성 보조값으로만 사용한다.

Setup은 다음 clock 전까지 데이터가 도착해야 하는 조건, hold는 clock 직후 일정
시간 데이터가 바뀌지 않아야 하는 조건이다. Recovery와 removal은 비동기 reset
해제와 clock edge 사이의 안전 간격을 검사한다. 네 종류 slack이 모두 양수이므로
현재 분석 조건에서는 통과했다. 다만 removal +0.043 ns는 작은
양의 여유이므로, 공식 PDK나 다른 전압·온도·배치 조건으로 옮기면 반드시 다시
검증해야 한다.

DRC(Design Rule Check)는 배선 폭·간격 등 구현 rule 위반을, connectivity check는
끊어진 net이나 의도하지 않은 연결 문제를 찾는다. 두 검사의 0/0은 현재 digital
core 배치·배선 database가 이 reference flow의 검사를 통과했다는 뜻이다. Pad ring,
package, foundry sign-off DRC/LVS나 제작된 silicon 측정까지 완료했다는 뜻은 아니다.

아래 이미지는 구조 예상도가 아니라 최종 배치·배선 database를 Innovus에서 다시
열어 직접 출력한 화면이다. 작은 사각형은 배치된 표준셀이고, 여러 색의 선은
전원망과 신호 배선이다.

## 6. 전력과 timing 수치의 해석 한계

전력 수치는 library model, 배선 기생성분, clock와 입력 활동 가정으로 계산한 tool
estimate이며 실제 chip에서 측정한 값이 아니다. 특히 vectorless power와 VCD
power는 입력 활동을 주는 방식이 다르므로 서로 절대값을 직접 비교하지 않고,
각 방식 안에서 P7과 P8의 상대 차이를 본다.

Gray state는 매 service decision마다 내부 우선순위 bit 하나만 바뀐다는 보장을
준다. 그러나 sparse traffic에서 실제로 선택되는 source 주소는 빈 주소를 건너뛸
수 있으므로, 모든 workload에서 output bus가 매번 한 bit만 바뀐다고 보장하지
않는다. 106회라는 값은 고정된 101-event workload의 측정치다.

2FF CDC의 192-point phase sweep은 digital protocol과 event accounting을 확인한다.
아날로그 metastability의 발생 확률이나 MTBF를 silicon에서 측정한 결과는 아니다.
공식 공정으로 port할 때는 해당 library의 synchronizer characterization과 CDC/STA
조건을 다시 확인해야 한다.

Recovery/removal slack도 STA가 `rst_n` 입력 도착에 둔 가정 아래 계산한 값이다.
외부 reset이 임의의 clock 위상에서 deassert될 때의 모든 analog 위험을 이 숫자만으로
증명하지 않는다. 두 단계 release 구조와 clockless reset simulation은 디지털 동작
근거이며, 공식 공정에서는 reset-domain crossing과 silicon 조건을 별도로 검토해야
한다.

## 7. 대안 구조를 함께 만든 이유와 최종 제외 판단

Ablation은 한 번에 한 구조 요소를 바꾼 실험본을 비교해 어느 아이디어가 실제
PPA에 기여했는지 확인하는 방법이다. 아래 후보도 기능 검증을 통과했지만, 같은
180 nm 합성 비교에서 P8-DG-SCR보다 좋은 최종 절충점을 만들지 못해 주 설계에서
제외했다. “동작하지 않는 설계”가 아니라 “최종 PPA 대표로 선택하지 않은 설계”다.

| 후보 | 시험한 아이디어 | 최종 제외 이유 |
|---|---|---|
| P8-DG | Binary-to-Gray 변환을 없애고 direct Gray만 적용 | P7과 같은 순서와 공정성은 유지했지만 shared tree, vector acceptance, reset partition을 모두 결합한 SCR보다 면적·전력 Pareto가 낮음 |
| P8-DG-PR | ACK/valid 17개는 비동기 reset, pending/epoch은 동기 clear로 분할 | 비동기 reset FF를 19개까지 줄였지만 SCR의 2개보다 많고, 출력 isolation을 사용한 SCR보다 최종 면적 이점이 작음 |
| P8-X2 | Binary epoch의 Gray encoder XOR 일부를 줄인 2-XOR 순서 | Full cycle 전환이 18회로 full Gray의 16회보다 많고, 101-event workload도 112회로 P8의 106회보다 많음. Genus area 6,626.189 µm², VCD power 0.663896 mW로 SCR보다 큼 |
| P8-GR/Ring | `out_addr`를 마지막 grant pointer로 재사용해 epoch FF 4개 제거 | FF는 71개로 줄었지만 공정한 cyclic search 조합 논리가 커짐. 101-event 전환 114회, Genus area 6,606.230 µm², VCD power 0.642428 mW로 SCR보다 큼 |

Ring은 P8-DG-SCR보다 FF가 4개 적지만, 최종 합성 area는 오히려 3.49% 크고 VCD
power도 3.75% 높았다. X2는 SCR보다 area가 3.80%, VCD power가 7.22% 높았다.
이 결과는 “FF 수를 가장 적게 만드는 것”과 “표준셀 전체 면적·전력을 가장 작게
만드는 것”이 같지 않음을 보여준다.

## 8. 2차 설계과제에서의 재사용 범위

P8-DG-SCR은 2차 과제의 전체 연산 기능을 대신하는 회로가 아니라, 여러 비동기
event source를 받아 안전하게 저장하고 하나씩 내보내는 **입력 전단 transport/
scheduler IP**로 재사용할 수 있다.

```text
16개 뉴런·센서의 event 요청
        ↓ 4-phase REQ/ACK
P8-DG-SCR: CDC + pending + 공정한 선택
        ↓ out_valid/out_ready + 4-bit source ID
2차 과제의 event router, neuron update engine 또는 accelerator core
```

재사용 시 지켜야 할 경계 조건은 다음과 같다.

- 각 source는 REQ를 ACK가 올라올 때까지 유지하고, ACK가 내려간 뒤 다음 event를
  시작한다. 현재 pending 깊이는 source당 1이다.
- 수신기는 `out_valid=1`일 때만 `out_addr`를 해석해야 한다.
- Reset 해제 후 정상 동작 전에 두 번의 controller clock edge를 공급한다.
- 현재 RTL은 16 sources와 4-bit source ID로 고정돼 있다. Source 수를 늘리면
  synchronizer 수, pending 폭, selection tree와 fairness bound를 함께 다시 설계하고
  CDC·기능·PPA를 재검증해야 한다.
- Timestamp나 추가 payload가 필요하면 이 4-bit 주소 bus에 무리하게 섞지 말고,
  source ID로 별도 payload memory를 조회하거나 interface를 명시적으로 확장해야 한다.

따라서 이 설계의 재사용 가치는 전체 과제 기능 충족이 아니라, 2차 과제에서도
반복해서 필요한 **비동기 발화 수집, burst 완충, 공정한 단일-lane 전송**을 검증된
독립 블록으로 가져갈 수 있다는 데 있다.

## 9. 결론

P8-DG-SCR은 P7-GE의 2FF CDC, 16+1 event 저장, early ACK, 단일 4-bit bus,
clock당 최대 1 event, 16-service-decision 공정성과 출력 순서를 모두 유지했다.
직접 Gray 상태, 공유 OR tree, vector 접수식과 reset partition을 결합해 상태 수를
줄이지 않고도 서버 제공 FPR 180 nm reference kit의 post-route cell area를
5.03%, vectorless power 추정치를 4.58% 줄였다.

그 대가로 post-route core setup slack은 1.115 ns 줄었지만 여전히 +3.235 ns이고,
CDC max-delay +0.201 ns, hold·recovery·removal도 모두 양수다. RTL/gate 기능, CDC, 공정성, reset, Xcelium,
LEC 75/75, DRC/connectivity 0/0을 통과했으므로 P8-DG-SCR을 현재 180 nm 잠정
비교의 최종 PPA 대표로 선택한다. 공식 공정이 확인되면 동일 RTL과 workload를
해당 library에서 다시 합성·배치·배선해 이 결론이 유지되는지 확인해야 한다.
